# Qwen 主导的金融信息采集

在 `D:\financial_data_project2` 使用原有 `finance_crawler` 环境。正式结果放在 `data/CN/`、`data/US/`、`data/GLOBAL/`，每篇原文单独保存为一个 JSON 文件。

当前新增美股SEC目录发现，`search.discovery_mode`支持search/direct/hybrid，实际模式以config.yaml为准。填写`search.sec_edgar.tickers`或ciks按公司发现；两者留空则按日期范围遍历季度申报目录。完整用法、预算、续跑和边界见[美股SEC目录发现说明](US_DIRECT_DISCOVERY.md)。下文的Tavily规划和搜索预算仅在search/hybrid模式生效，direct模式不调用Tavily；complete_history=true时也会自动续跑SEC目录。

## 运行

先修改 `config.yaml` 的市场、方向、公司、日期和网站。原有 Tavily 密钥与本机代理配置已保留。

```powershell
conda activate finance_crawler
cd D:\financial_data_project2
python main.py
```

也可直接运行：

```powershell
& C:/Users/marti/anaconda3/envs/finance_crawler/python.exe D:/financial_data_project2/main.py
```

历史broad模式先按年份公平发现，再细化自然月窗口。每轮搜索后自动分批处理当前范围候选；当前 `search.complete_history: true` 会继续下一轮发现，直到有限搜索计划遍历完或服务/任务失败需要复核。Ctrl+C可停止，已提交搜索与候选进度保留。实时模式按配置间隔开始下一轮。

```powershell
python main.py --validate-config  # 检查配置，隐藏密钥，不进行搜索
python main.py --doctor           # 检查本地 Ollama 是否有 qwen3:8b
python main.py --preview-history  # 查看年度/月份计划，不联网、不调用模型
python main.py --repair-mappings # 校验备份后纠正旧证券属性；不搜索、不调用Qwen
python main.py --retry-failed-searches # 修复网络/配置后，重试失败历史搜索并正常运行
python main.py --resume           # 可选：跳过搜索，自动处理现有队列
python main.py --reprocess-saved  # 自动分批重读历史来源；无缓存时重新获取原URL
python main.py --once             # 可选调试：仅处理一批后退出
```

直接运行 `main.py` 即可。每轮发现遵守 `max_queries_per_cycle` 次实际搜索预算，随后每批最多处理 `max_documents_per_cycle` 篇；正文续批不会重放已完成的搜索。完整历史模式在当前候选处理后继续下一轮未完成发现，因此总搜索次数可超过80，见下文预算说明。已保存URL不重复提炼；`--force`可强制重读，通常不需要。

Qwen 调用上限也是每批上限。达到调用次数时会自动开新批次并复用缓存续读长文，同一记录最多自动跨批续处理3次，防止卡住。网络失败、日期不足、解析失败或上下文不足的记录本次留待复核，继续处理其他候选，不在后续批次反复重试。

正常采集不需要再手动执行 `--resume`；它仅用于不想新增搜索、只继续现有队列的场景。`--once` 才表示处理一批后退出。最终终端和 `logs/latest_run.json` 会区分“未尝试”和“失败待复核”，汇总所有自动批次。

### 先检查，再提炼

现在每篇按“范围和去重 → 获取/复用可读主正文 → 来源日期及时间范围检查 → 相关性筛选 → Qwen正文提炼与合并 → 输出校验和保存”执行。逐篇检查通过即可继续，不必先下载整个候选队列。可核验日期超出配置范围时，在正文提炼前跳过；正文损坏、没有完整日期证据或固定输入预算不足时，本轮不做正文提炼，保留待复核原因与必要原文。只有年份/月度、修改日期、报告期或PDF签署日均不能补猜为发布日期。

普通网页需要时由Qwen核验日期，已核对SEC申报索引与主文档的日期则直接复用。原始网址与重定向后的正式记录建立内部关联，重复出现时不再重复提炼；新别名也会在获取最终网址后先检查是否已保存。旧的可见正文v2缓存会重新获取，避免复用可能混有评论的正文；新正文优先绑定article，排除明确评论/推荐区域，并保留time datetime属性中的原始日期线索。

长文合并前会检查输入预算，必要时先整理中间摘要，保留关键事实、期间、数值限定词和观点归属，不截断原文冒充完整提炼。无法通过事实或预算校验的结果仍留待复核。实体、数字、摘要幻觉等问题需要模型输出后才能检验，前置检查不能保证后续绝不失败。日志新增“前置检查汇总”，列出检查、通过、提前跳过与待复核篇数；正式JSON仍为10字段，config无需增加开关。

正文缓存和已校验的SEC目录候选会省去重复标题初筛，正文仍由Qwen判断用途、核对发布日期并提炼。hybrid的搜索与SEC独立续跑，一个渠道暂停时会继续另一个可用渠道。JSON、副本及审计共同提交，未完成保存先恢复；后续清理失败不会丢弃已核验结果。效率日志中的“省去初筛”和“恢复事务”不代表额外生成了新的文章。

若安排“等当前采集自然结束后再运行”，项目的 `run_after_current.py` 会绑定原进程PID和创建时间等待，按届时的 `config.yaml` 启动一次。状态查看 `.runtime/restart_after_current.json`：waiting表示仍在等待，running表示新一轮已启动；terminal_log指向该轮输出日志。若已手动启动新采集器则不重复启动。该辅助程序不会停止原进程，也不会无限重启失败任务；常规使用仍直接运行 `main.py`。

## 配置

- `monitoring.markets`：`["CN", "US"]`，可只保留一个市场。
- `monitoring.directions`：默认 `all` 自动覆盖全部金融相关方向；也可填 `["银行业", "半导体"]` 自选。`securities` 可填写关注的股票/公司；空列表表示按方向搜索，不是采集全市场全部股票。
- `include_keywords` / `exclude_keywords`：提供给 Qwen 的搜索和筛选偏好。include_keywords 不要求文章必须字面命中，可设为 `[]` 让模型自行选择搜索角度。
- `collection.mode`：`historical` 指定起止日期，格式 `"2026-11-01"`；`realtime` 时两项日期设为 `null`。
- `max_queries_per_cycle`：每轮发现的实际HTTP搜索上限，当前80，可设置1～200且至少等于启用市场数。`complete_history: false`时也是本次运行的搜索上限；true时可自动续轮，总请求会超过80。每次最多返回20条。
- `search.complete_history`：当前true，自动遍历有限历史计划；设false则本次最多80次搜索，保存断点，下次直接运行main.py继续。任务计划完成不等于穷尽全网。
- `search.undated_fallback`：当前true，严格发布日期搜索为空时独立回退一次宽搜索；回退请求同样占预算。搜索估计日期只做线索，最终必须核对原文。
- `max_candidates_per_query`：每次最多返回多少条搜索结果。`max_documents_per_cycle`：每批最多评估多少个候选，默认运行会自动继续下一批。
- `search.provider`：默认 `tavily`，密钥填在 `search.api_key`；可改 `rss` 并填写订阅地址。Tavily 搜索与本地模型运行是不同组件。
- `search.discovery_mode`：`search`为原搜索发现，`direct`为美股SEC目录发现，`hybrid`同时启用。目录发现独立遵守sec_edgar中的页数和请求预算；两路共用后续Qwen/JSON流程。
- `search.website_mode`：`restricted` 按市场限制域名；`unrestricted` 不限制网站。`exclude_domains` 两种模式都生效。
- `search.market_domains.CN` / `.US`：当前分别16个、34个来源域名，可随时增删，详见下方说明。
- `ollama`：本地 `qwen3:8b`，默认关闭思考，4096 上下文，串行处理，适合先在 8GB 显存环境验证。长文分段概括再合并，不逐句生成记录。每批调用次数由 `max_calls_per_cycle` 控制；整次自动采集的总调用次数可能高于这个值。
- `fetch.proxy_url` / `allow_fake_ip`：保留已有本机代理和 Fake-IP 兼容方式；不会修改 Clash Verge 或 TUN 配置。
- `fetch.delete_raw_after_extract`：默认 `true`；正式JSON及内部审计均写入并校验后，才清理该篇对应的原文缓存。失败和待处理原文保留。

限制网站表示搜索和下载只允许这些域名，不保证网站开放全部内容，也不等于逐站穷尽所有历史公告。登录、验证码、robots 或网络拒绝会留在待处理日志中。

## 模型负责什么

`Qwen 搜索规划/SEC目录 → 候选 → Qwen 判断是否下载 → Crawl4AI/HTTP 或 PDF 读取 → Qwen 判定用途、来源发布时间、分类、关键词、段落摘要、股票实体、涉及行业和影响范围 → 独立 JSON（共10字段）`。

有效提示词位于 `prompts/*.md`，由 `qwen_agent.py` 启动时加载。主要修改正文取舍时编辑 `prompts/read.md`，整篇合并编辑 `prompts/merge.md`，检索筛选编辑 `prompts/screen.md`；完整职责见 [提示词说明](prompts/README.md)。先核对原始发布时间，再分段提炼，不让脚注或报告期间重选日期；主要产业只用于命名。

搜索词允许中文、英文和混合表达，无固定词数和旧140/220字符限制。行业覆盖规划现在输出groups，每组direction/market对应一个任务，queries列表在模型schema中最多2条；US附英文行业提示，仍不因查询语言拒绝结果。程序保留已合格组及其中的有效查询，只对缺失/不合格组补规划；超额项局部去重截取，不重写其他组。direction与market、网站、日期和实际请求/模型预算继续按config执行。

旧历史搜索断点会在下次运行时兼容到稳定的配置标识，保留已完成项、游标、正在执行的严格/宽检索阶段和已有计划；放宽提示词不会使同配置下已提交任务从头重搜。旧状态条目保留，不清空队列或数据。正在运行的进程仍使用启动时的代码；正常Ctrl+C后重新运行main.py才加载新规则。本次放宽针对搜索词，摘要继续遵循原文语言与日期、实体等校验。
Python 负责执行请求、限制范围与调用次数、缓存、去重和保存，不再要求 Qwen 填写数值事实表、主体映射、逐句证据块或预测分数。Qwen 可以概括有归属的专家观点，不自行预测股价。

HTML 优先保留主文章及其嵌入式正文，并处理 UTF-8/GBK 编码。PDF 先恢复可读文字，再交 Qwen 整理；没有可读文字的扫描件当前留待处理，不冒充已经读完。无法读取的乱码不会因为交给模型就自动变成可信信息。

## 独立文件命名

`原始时间_分类_主要产业_来源网站.json`

原始时间优先使用来源时区的 `YYYY_MM_DD_HH_mm`，只有日期则用 `YYYY_MM_DD`，不补造时分。秒数和时区仍保留在 JSON 的“时间”字段中。

分类与主要产业均由 Qwen 提炼；产业只用于文件名。来源键由原始 URL 的域名确定，例如雪球 `xueqiu`、巨潮 `cninfo`、财联社 `cls`、证监会 `csrc`、上交所 `sse`、SEC `sec`、NASDAQ `nasdaq`。其他来源按域名生成简称。

同一分钟、同分类、同产业、同网站可能存在多篇文章，重名时自动追加 `source_id`，避免覆盖。Windows 文件名中的非法字符会替换；同一记录更新分类、产业或市场时，保存新文件后移除旧副本。

旧的三个 JSONL 已逐条迁移，原文件在 `archive/jsonl_records_*.zip` 中经过逐字节校验后保存，活动数据目录不再同时保留 JSONL。后续运行 `main.py` 会直接保存独立 JSON，不需要手动拆分。

## 内容与时间信息

```json
{
  "source_id": "由规范化URL生成的稳定ID",
  "url": "原始文章URL",
  "时间": "2026-11-02T20:30:58+08:00",
  "分类": "监管政策",
  "关键词": ["政策主题", "行业或公司"],
  "主要内容": "字段格式示意；实际内容须来自原文。",
  "股票实体": [],
  "涉及行业": [],
  "影响范围": ["market"],
  "时间信息": {
    "publication_precision": "second",
    "first_seen_at": "2026-11-02T12:31:00+00:00",
    "fetched_at": "2026-11-02T12:31:05+00:00",
    "feature_available_at": "2026-11-02T12:31:20+00:00",
    "availability_basis": "extraction"
  }
}
```

上述仅示意格式，不会写入正式文件。`source_id` 用于 URL 去重，不是股票编号。正式数据没有额外的 evidence、paragraphs、semantic_candidate、ready 等字段。

新增三个分析字段，所有市场保存方式相同：

| 字段 | 格式与含义 |
| --- | --- |
| 股票实体 | 对象列表，例如`[{"名称":"Apple Inc.","股票代码":"AAPL","交易所":"NASDAQ"}]`。仅保留原文可核验代码的证券；没有代码使用[]，不影响文章入选。公司名仍保留正文/关键词，名称或交易所未知时可为null；支持同篇多家公司，不把代码当记录ID |
| 涉及行业 | 对象列表，例如`[{"名称":"Semiconductors","依据":"inferred"}]`。explicit为原文明示，inferred为有原文支持的语义归类，legacy_metadata为旧文件已有分类恢复；行业名跟随正文语言，无可靠信息为[] |
| 影响范围 | company/industry/market多选列表，分别表示公司、行业、市场信息层级；未知为[]。表示后续相关性分析的范围，不代表已证明影响股价，更不是涨跌标签 |

字段中的原文引文只进入内部审计，正式JSON不增加逐句证据。正文分段提炼和合并会保留源笔记核验过的实体、行业和范围，避免合并时丢失；原文无代码或交易所时不按常识补全。

证券校验集中在security_grounding.py。公司名称不能充当代码，名称与代码须有局部声明、代码/简称头部或对应表格行等关系证据；同段共现不算正确配对。仅为有效摘要选中的名称/代码补保留原文明示代码，不重新追加未选中推荐内容。没有可核验代码时正式股票实体为[]，公司名仍进入摘要/关键词；不按常识补代码。DIY、IMF等普通行业/机构缩写不再一律作为股票代码拦截；模型补猜的证券标记会局部清理，正文事实保留，清理信息仅放内部审计。行业语义归类标记inferred，不冒充原文明示或股票走势预测。

发布日期仍是正式保存的必要条件；修改/生效时间不替代首发。校验分别使用与引文匹配的日期元数据、文章头部或合格PDF证据块，避免另一块dateModified误伤合法新闻稿落款。robots.txt明确不允许的路径仍留待复核，不绕过访问限制。

`--repair-mappings`可单独纠正旧JSON的证券属性：依据匹配哈希的旧审计引文重新校验，先备份受影响JSON和审计并读回核对，再清空格式错误或缺少配对证据的代码/交易所。它保留名称、原摘要、关键词、发布日期和文件名，更新本版元数据可用时间，GLOBAL视图与审计共用可恢复事务；报告为logs/mapping_repair.json。无法核验的合法形状代码不会按常识重新映射，而是在报告中列出。该维护命令不重读原文，不能声称完成了全文事实重审。

新校验版本会更换Qwen缓存键，旧模型输出不会绕过新规则。当前证券抽取仍不等同于历史证券主表解析，也没有直接生成StockMixer行号；历史ticker有效期、发行人/证券/股类及dataset股票轴关联需单独核验。

旧的六/七字段记录可以在写入锁空闲时单独升级：

```powershell
python main.py --upgrade-records
```

该命令不搜索、不下载、不调用Qwen，也不消费采集队列。先将旧JSON及相关审计按SHA-256校验备份到archive，再补齐三个字段；股票实体仅从内容哈希匹配、且引文可核验的旧审计恢复，行业可恢复自原文件名中的旧分类并标记legacy_metadata。范围仅在恢复到股票实体时保守标为company，其余未知留空，不把当前目录的CN/US/GLOBAL当成影响范围。已有正文、来源日期和路径保留，新增元数据的feature_available_at更新为升级时刻并标记migration。GLOBAL所有副本及审计共用可恢复事务；升级报告为logs/analysis_schema_upgrade.json。正常main.py启动也会先进行同样的升级。

没有原文依据的旧记录不会因结构升级而自动获得完整语义。需要重新从原始来源提炼时使用现有--reprocess-saved，并遵守当前来源/日期范围；不要把[]视为已证明没有相关信息。当前采集进程持锁时先正常停止，不能并发迁移。

`时间` 只记录原始来源的发布日期/时刻。只有日期则保存 `YYYY-MM-DD`，不伪造零点或分钟；有可靠时刻则保留明确时区。事件发生日与政策生效日可写入摘要。日期原文引用留在内部审计，不重复写入正式JSON。无法确认发布日期的文章不会进入正式文件。

`时间信息`直接保存在每条JSON中，不需要训练时另外寻找日志：

| 字段 | 含义 |
| --- | --- |
| publication_precision | 来源时间精度：date/minute/second；不是采集时间精度 |
| first_seen_at | 系统首次记录该候选的时刻；历史未知为null |
| fetched_at | 本次摘要所用正文实际获取时刻；旧缓存未记录时为null |
| feature_available_at | 当前这版文本完成整理、可交付给下游的时刻；重新提炼会更新 |
| availability_basis | extraction=实际本轮提炼；verified_audit=从内容哈希匹配的旧审计恢复；migration=旧记录无可信时刻，以本次迁移时刻作为保守界限 |

系统时刻统一为UTC、带`+00:00`，包含日期和时分秒；来源“时间”保留其已有来源时区。只有日期的来源不会补成午夜。没有可靠历史记录时，不从文件修改时间或发布日期推算采集时刻。

回测的决策时刻必须晚于该版文本的`feature_available_at`，还需核对来源发布时间、时区及交易时段。不能把2026年才下载并概括的2022年网页，直接当作2022年已经可用的文本特征。migration标记的时间是保守界限，不声称还原了历史真实到达时间。要做历史时点回测，需另有可信历史版本和到达记录；增加这些时间字段本身不能消除所有泄漏。

一篇原文合为一条摘要，同一 URL 更新后可替换原记录。不同网站转述同一新闻仍可能各有一条，当前没有做跨来源的语义去重。

这些是可读取的文本输入，不是已经验证过的涨跌标签。纯数值时序模型仍需将摘要编码为文本特征，并与股票及交易日对齐；历史来源日期也不证明该条摘要在当时已经生成。

## 扩大采集配置

当前 `directions: all` 自动轮转52个行业及宏观搜索主题，日期以当前 `collection.start_date/end_date` 为准。此前每次只有4次搜索、每次最多15条，容易遗漏长行业列表；现在是每次最多80次搜索、每次最多20条。

```yaml
collection:
  max_queries_per_cycle: 80         # 每次运行的搜索请求预算
  max_candidates_per_query: 20      # 单次最多返回20条
  max_documents_per_cycle: 10       # 每批处理10篇，自动连续处理后续批次
search:
  strategy: broad                  # broad扩大覆盖；focused保留原来的少量搜索词模式
  topic: general                   # 扩展到新闻以外的公告、帖子、问答等；仍受网站名单限制
  date_window_days: 31              # 年度覆盖后，按自然月细化；每段不超过31天；0仅做年度覆盖
  rotate_sources: true             # 月度细化轮转来源；年度搜索使用该市场全部允许域名
  complete_history: true           # 自动续轮，总搜索可超过每轮80次
  undated_fallback: true            # 严格日期为空时独立回退一次，同样占搜索预算
```

Qwen 每次为少量行业生成中英文查询，覆盖行业和市场组合；工具负责网站和日期窗口。查询词不再自行添加2024等年份，日期由搜索接口限制。每轮会输出覆盖的行业、网站、时间段、搜索返回数、新增线索、已保存忽略数和队列已有数。

计划、已提交查询、失败任务和严格/回退阶段保存在 `.runtime/simple/state.json` 的discovery中。同配置重启从断点继续；行业、日期、网站等范围变化会建立新计划。正文续批不重复搜索；完整历史模式在本轮候选处理后才进入下一轮发现。进程在请求结果尚未提交时中断，该未确认请求可能重试，URL仍会去重。

80×20=1600是每轮返回条数的理论上限，包含重复或无用内容，不保证新增1600篇。完整历史模式可有多轮，会增加Tavily额度消耗；小规模验证可设complete_history=false且max_queries_per_cycle=2。--once只限制正文为一批，不会降低搜索预算。

## 全方向与关键词的含义

不需要逐项填写行业。当前配置已设置 `monitoring.directions: all`，内部自动轮转52个主流行业、宏观政策和市场主题。`directions: ["all"]` 也可用，省略该项时默认all。自选行业时填普通列表，例如 `["银行业", "半导体"]`；不要与all混写。

内置主题用于组织搜索，不是行业硬白名单。all模式下不因文章所属行业未列在内置主题中就排除；Qwen依据金融相关性与信息价值筛选。受每次搜索预算约束，并非一次穷尽全行业或全网。

include_keywords 是偏好，主要用于生成搜索词和Qwen初筛，不是必须出现某个词才下载的程序规则。未字面命中但有实质市场信息的文章仍可保留；这些词仍会影响搜索结果分布。若不想人工指定搜索角度，可以留空，程序不会偷偷补回固定的公告/财报/政策词表：

```yaml
monitoring:
  directions: all
  include_keywords: []
```

本次仅将directions改为all，当前原有include_keywords词表保留；上述空列表是可选写法。最终JSON中的“关键词”由Qwen从原文另行提取，不是把配置词表复制进去。保存还须满足正文可读、信息有价值及来源日期可核对等条件。

配置在程序启动时加载，修改后在下一次启动生效；运行中的采集任务继续使用启动时的配置。

## 更宽的发现与更完整的摘要

Qwen为每组行业/市场规划1至2种简短搜索角度，网站与日期窗口仍由程序轮转。include_keywords只是偏好，未命中某个词仍可下载；普通业绩、订单、股东变化、公司问答、宏观统计和有归属的分析帖子都可进入。摘要不足以判断时优先读取正文，明确的目录、广告和灌水才在搜索阶段排除。日期核对、正文质量与网站范围继续生效。

主要内容尽量保留原文提及的公司/股票、原文代码、发生的事、财务期间、关键数字与单位、比较基准、原因、条件及实施状态。通常中文约200至350字、英文约120至190词；短讯更短，实质事实较多可略超，不为凑字数扩写；关键词包含相关公司原名和原文证券代码。原文没有代码时不根据常识补全。Qwen内部引用证券证据供校验，正式JSON保留既定十字段，包含时间信息、股票实体、涉及行业与影响范围。

英文原文输出英文主要内容和英文关键词；已有中文摘要不会自动全部改写。论坛只整理主帖，不把后续评论混入早期主帖日期；独立评论需要自己的链接与来源日期。专家预测可作为有归属的原文观点概括，不变成程序自行预测的收益率。

## GLOBAL同时供两个市场读取

被Qwen判定为GLOBAL的一条信息保留在 `data/GLOBAL/`，同时在 `data/CN/` 与 `data/US/` 保存相同JSON（包括时间信息）。因此只读取某一个市场目录即可包含公共市场信息，不需要额外拼接GLOBAL。三份文件的source_id与内容相同，属于同一条记录；汇总唯一篇数不会重复计数。联合训练或合并三个目录时，按source_id去重。

启动时自动把旧GLOBAL记录补齐到CN与US，无需重新调用Qwen。该同步与正常采集共用单写入锁；运行中的旧进程不能直接使用刚修改的代码。下一次启动后生效，避免两个进程同时修改数据。

## 原文清理与历史数据升级

每条正式记录及GLOBAL副本成功写入并读回核对后，程序写入 `.runtime/simple/audit/<source_id>.json` 并校验，再按精确URL及正文哈希删除对应的 `.runtime/simple/pages/<source_id>.json`。已知验证HTML/PDF仅在原始字节哈希匹配时清理。不会递归清空目录、删除失败原文、用户文件或archive旧备份。设 `fetch.delete_raw_after_extract: false` 可保留后续原文缓存。

内部审计保留来源日期引用、证券证据、模型版本及摘要哈希，不保留完整原文；必要的时间信息同时进入正式JSON。旧记录只有在重新提炼、校验成功后才执行相应清理。需要用新提示词升级旧记录时，可选择 `python main.py --reprocess-saved`：优先读取尚在本地的原文，否则重新下载原URL；不会把旧摘要冒充原始正文。该命令仍遵守当前市场、网站及日期范围。

## 对接文本编码器与收益率时序模型

读取每条“关键词”和“主要内容”作为文本编码器输入；股票关联优先使用原文明确的公司名/代码。缺代码的行业或宏观新闻可作为行业/市场上下文，不能硬分配到某只股票。GLOBAL信息对两个市场可用，合并时按source_id去重；不同URL转载同一新闻尚未自动做语义去重。

“时间”是来源发布时间；每条JSON的“时间信息.feature_available_at”记录当前文本的可用界限，二者不能混同。历史网页可能后来修改，当前下载的旧日期文章不能据此视为当时已知。严格回测需另行核对历史版本、发布时间时区与交易日，收盘后消息顺延到下一个可交易窗口；训练/验证/测试按时间分割，文本编码和聚合也须避免未来信息泄漏。来源日期无法确认时继续保留待处理，不为增加数量而猜日期。

这些改动扩大可进入模型的事实文本，不能保证提升预测收益。实际验收应抽样对照原文检查主体、代码、日期、数字和条件，并分别统计唯一有效记录数、待处理原因、摘要错误率、重复率及各行业/来源覆盖。

## 历史覆盖、断点与年度验收

历史broad模式的有限计划分两层：先对每个方向依次检索各年份及市场，再按自然月细化并轮转方向和来源。配置截取到年中时，相应年度及月份按实际起止日裁剪。年度检索使用该市场全部允许域名，月度细化按rotate_sources选择单个来源。Qwen生成搜索角度，程序只追加用户指定年份，不允许模型随意编年份。

当前US、2012-01-01至2022-05-25、52个方向，对应572个年度任务及125个月度任务，共697个任务。最初11个年度任务依次覆盖2012至2022，不再集中于2022年最后一个月。每个任务至少一次搜索；严格日期检索为空且启用回退时，会多一次请求。697是有限搜索计划规模，不是网页数，也不是网站全量历史索引。

当前complete_history=true：每轮最多80次HTTP搜索，处理完本轮候选后继续下一轮，直到计划遍历完或失败/额度限制需要复核。因此总搜索次数会超过80，可能耗时较长并使用更多Tavily额度。若只想每次最多80次搜索，设false；下次main.py从已提交断点继续。--resume会跳过发现阶段，不能用来推进未完成的历史搜索。--once不会自动续发现轮次。

搜索阶段不会因Qwen单批30次调用预算直接停止；会保存本地计划并开启下一模型批次。组合规划未通过时，回退为单行业/市场Qwen重规划，避免整组失败直接漏掉多个年份。已经提交的查询不重放；严格查询完成但回退尚未发出时，会准确续到回退。搜索失败单独记录，连续失败或服务授权/额度受限时暂停，不能报告为覆盖完成。修复服务问题后运行 `python main.py --retry-failed-searches` 重试；失败任务每次运行不会无限循环。

旧队列保留在内部state中，按collection_scope逻辑隔离，不计入当前候选篇数和模型预算。没有旧范围标记的历史候选，仅在其正文明确发布元数据可核验且范围相符时采用；其他候选保留，等本次搜索重新发现并绑定范围后激活。标题/URL含2016等年份、搜索引擎估计日期，不足以证明属于当前历史区间。

保存前先由Qwen在文档级核对一次原始发布时间，再分段概括和合并正文；后段事件、参考文献或脚注不能重定文章日期。修改/更新时间不能冒充原始发布日；PDF只有签署落款也不足以证明公开日期。日期无法核实、访问拒绝、乱码或模型输出未通过验证时，保留原文与待复核状态，不生成伪造日期的正式JSON。已经发现日期依据不合格的旧记录，会先验证备份再移入 `.runtime/simple/quarantine/` 并重新排队，不直接丢弃。

终端及logs/latest_run.json新增year_coverage、years_without_records、quality_status、discovery.tasks_done/tasks_remaining/complete及inactive_pending等统计。每年显示搜索数、返回数、当前范围JSON数量；计划完成但某年仍为0时明确显示数据缺口，不能推断该年没有信息。具体记录仍保持六个内容字段加时间信息，位置和命名不变。

Tavily返回的published_date只是搜索服务对发布或更新时间的估计，作为候选线索保留，不进入最终时间字段。严格日期与未知日期回退分别执行，详见[官方接口说明](https://docs.tavily.com/documentation/api-reference/endpoint/search)。
