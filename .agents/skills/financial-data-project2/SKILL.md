# financial_data_project2

## 核心目的

为A股、美股构建自然语言市场信息数据集。后续将关键词和连贯的主要内容输入语言模型，形成文本特征，融入股票预测时序网络，辅助股票收益率预测。当前采集器负责准备可信输入，不自行训练或修改主干网络，不把Qwen预测当作收益率标签。

优化应同时增加有效记录的数量、来源和内容的丰富度，以及事实精度、历史覆盖和训练可用性。不能靠重复文件、碎片句子、无用套话、猜测日期或股票代码增加数量。数据量多不等于信息有效，也不代表预测效果已经改善。

## 项目与环境

- 工作项目为 `D:\financial_data_project2`。项目代码、配置、缓存、日志和数据修改限定在该目录；旧项目不作为默认写入目标。先读项目 `AGENTS.md`，按任务阅读 `README.md`、最新实现状态和相关代码。
- 沿用 `finance_crawler` 环境、本机Ollama和 `qwen3:8b`；硬件为RTX 5070、8GB显存。优先串行推理、合理上下文和分段合并，默认不需要思考模式。不要借优化修改全局环境、Clash Verge或TUN。
- `main.py` 是采集入口，`config.yaml` 决定市场、日期、方向、网站和预算。每次核对实际配置，不固化某次运行的日期、任务数或网站数量；密钥不得进入技能、提示词、日志或示例。

## 架构分工

- Crawl4AI负责HTML获取与主正文清理；可用接口、RSS和公开归档用于发现或取得适合的数据。PDF先恢复可读文字再送模型；扫描件、乱码或访问拒绝不因交给Qwen就成为可信正文。
- Ollama在本机提供Qwen推理服务，不默认改用远程模型。
- Qwen参与搜索角度规划、相关性筛选、文章级发布日期判断、分类、主要产业、实体与关键词提取，以及成段摘要。保留原文事实和有归属的观点，不自行补充市场结论或预测收益率。
- Python负责实际请求、网站与日期范围、调用预算、发布证据校验、队列隔离、断点、去重及可靠保存。模型的判断不替代这些执行约束。

## 丰富度与精度

覆盖新闻、公告及财报、宏观统计、监管和政策、行业供需、公司经营、投资者问答、论坛帖子和专家评述。优先保留原始披露和可追溯来源，也保留有实质内容的独立观点；专家预测必须说明是其观点，不能写成已发生事实。

按当前config分别使用CN/US来源范围，允许用户增删。`directions: all` 不要求人工逐项填行业；内置主题用于组织检索，不是硬行业白名单。`include_keywords` 是搜索偏好，不是必须字面命中的下载门槛。初筛允许信息不全但可能有用的文章进入正文判断，明确目录、广告、灌水才排除。

摘要保留“涉及谁、发生什么、何时/哪个财务期间、关键数字及单位、比较基准、原因、条件、计划或实施状态”。股票名称和代码仅在原文出现时使用，重要名称和代码应进入关键词和正文。原文无代码时不按常识补全。区分事实、公司目标和作者判断；不过度压成一句话，也不为凑长度扩写。英文原文保留英文摘要和关键词，中文原文保留中文。

清除导航、推荐阅读、版权套话和重复段落，同时保留影响含义的数字、限制条件和归属。一篇主文章合为一条连贯记录；不把其他新闻或后续论坛评论合并进主帖，尤其不能套用早期主帖时间。

数据少时先检查年份/月度覆盖、来源分布、预算与搜索续跑、旧队列、访问失败和日期证据，再判断筛选是否过严；不要一律降低质量门槛。

## 历史覆盖与执行范围

让各年份先获得检索机会，再细化月份、方向和来源；保存已提交搜索、失败任务和回退阶段。模型单批预算耗尽应续批，不应悄悄终止整个历史发现。仅处理完候选队列不代表历史搜索已完成。

保留并隔离其他市场或日期范围的旧任务，不让它们抢占当前预算。没有可靠范围标记的旧候选不能凭标题年份激活；重新发现或核验明确发布元数据后再采用。来源不允许访问时保留原因，不绕过登录、验证码或明确限制。

区别每轮搜索上限和完整历史任务总请求量。`complete_history: true` 可以自动续轮，总搜索次数会超过单轮预算；变更前解释其实际含义，按当前用户授权执行。服务额度/授权受限或重试无进展时保存断点并停止相应阶段，不无限重试。创建或使用本技能不隐含启动整轮采集；用户要求停止后，不因排错、验证或重试自行恢复。

## 数据契约与时点正确性

- 正式数据为 `data/CN/`、`data/US/`、`data/GLOBAL/`，一篇一个JSON，市场目录内不额外套无意义子目录。文件名为原始日期或时刻_分类_主要产业_来源键，重名追加稳定ID防覆盖。
- 维持内容字段 `source_id`、`url`、`时间`、`分类`、`关键词`、`主要内容`，另有 `时间信息` 对象。保留原始链接。用户明确需要改契约时，同步迁移和下游兼容；不默认增加逐句证据、重复属性或涨跌预测分数。
- `时间` 表示原始来源发布日期/时刻。先在文档级核对并绑定，再分段提炼；修改时间、抓取时间、生效日、报告期间、参考文献日期、PDF仅签署落款，均不能冒充首次公开时间。搜索服务的日期估计只是线索。
- `时间信息` 保留 `publication_precision`、`first_seen_at`、`fetched_at`、`feature_available_at`、`availability_basis`。系统时刻为带时区ISO格式；来源精度只有日期时不造零点或时分。未知历史时刻为null，不从文件mtime推算。
- 当前这版摘要重新生成后，应更新其实际可用时间，不能沿用旧版本的更早时刻。旧记录只有匹配内容哈希的可信审计才能恢复历史提炼时间；迁移时刻只是保守界限，不证明历史到达时间。缺可靠发布日期的记录留待复核，不进入正式数据凑年份。
- GLOBAL同时供CN和US使用，三个目录的副本共用 `source_id`、内容和时间信息。联合读取时按ID去重，统计唯一记录而非物理副本。不同URL转载需在训练前检查近重复，不能仅依赖URL去重。

下游按原文明确的公司/代码关联股票；无代码的行业或宏观消息可作行业/市场上下文，不硬分配到某只股票。股票关联、交易日历和历史证券映射不得偷偷使用未来才知道的信息。

按预测决策时点检查文本是否已可用，处理时区、收盘后消息和只有日期的保守对齐。当前才抓取并概括的历史网页，不因发布日较早就能当作当时已知特征；历史修订版也需核对。训练/验证/测试按时间划分，编码器训练、标准化、聚合和收益率标签构造各自避免未来信息泄漏。详细网络改动属于后续单独任务。

## 保存与验收

原文清理遵循当前任务授权和配置：正式JSON、全部副本及审计写入并读回核对后，才按精确URL/哈希移除对应缓存。失败、待复核、隔离记录及旧备份保留，禁止为清理冗余批量清空数据目录。已知错误日期的旧记录应备份隔离后复核。

修改后运行对应回归检查，测试夹具和真实验证样本放隔离目录，不混入正式数据。配置/计划预览使用现有入口；完整采集仅在本次任务已授权时运行。分别报告离线测试、本地模型、真实搜索和真实下载，不能以JSON语法通过替代事实验收。

按年、月、市场、来源和方向检查覆盖与缺口，区分搜索返回、候选、成功正文、有效JSON、复用记录、失败原因和GLOBAL副本。抽样对照原文检查实体、代码、日期、数字、条件和摘要遗漏。搜索计划已遍历与语料已覆盖、JSON可读取与可用于某次回测，是不同的验收结论；不保证每年固定条数或未经验证的预测收益。
